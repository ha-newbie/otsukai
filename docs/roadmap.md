# ロードマップ

## MVP

- 日本語5タブ、レシピCRUD・検索・人数換算、週間朝昼夜献立・移動・日別人数。
- 在庫CRUD・期限・予定残量、材料自動集計、直接購入品、数量調整、カテゴリ別チェックと保存、購入分の一度だけの在庫反映。
- IndexedDB、バージョン付きJSONの検証・確認・復元、ファイル共有/ダウンロード、最終バックアップ、永続ストレージ要求。
- React/TypeScript strict・Vite・Tailwind・Dexie・Zod・PWA・Vitest・Playwright・GitHub Pages CI、GPLv3。
- AIProviderの契約、プロンプトコピー、構造化JSON手動取込。

## 次の開発

ホーム画面へのアプリ保存はユーザーから完了報告あり。オフライン・データ保持・ファイル共有・復元・更新は引き続き実機確認が必要。

1. **ユーザー指示でSign in with ChatGPT・外部レシピ取込を優先。** 汎用のURL/HTML/Recipe JSON解析、AIプロンプト・回答取込、保存前の編集を実装した。対象サイトを選び、利用条件・CORS・実データを検証する。
2. 直接認証は公式調査の結果、現在のiOS PWA単体では適合するフローを確認できず未実装。別実行環境を追加するか、手動連携を維持するかを決める。[調査・設計](ai-import.md)参照。
3. その後、購入チェックの連続タップ対応と実機のオフライン・バックアップ/復元・更新時のデータ保持を確認する。
4. 同じ週の複数回の買い物・調理時の在庫消費を共通設計とデータ移行を含めて実装し、実使用から食材名・カテゴリ・レシピ整理・操作性を改善する。

残件の優先度、現状、完了条件、着手条件は[backlog.md](backlog.md)にまとめている。

GitHub Pagesへの初回公開は完了。https://ha-newbie.github.io/otsukai/ を利用でき、以後はmainの更新で自動公開する。

## MVP後の独立タスク（未実装）

- ChatGPT直接接続: 優先調査済み。公式契約枠フローはloopback listenerが必要。Web本人認証は承認済みclientとbackendが前提。現PWAへの直接認証は未実装で、採用方式の判断が残る。
- 外部レシピのサイト別対応: 汎用構造化データ解析・条件付きCORS取得は実装済み。対象サイトの利用規約と実取得の検証・固有形式対応は残る。制限回避のプロキシは作らない。
- 店舗ごとの売り場・通路マップ、入口/出口を含む巡回経路、チェック連動。
- 任意クラウド同期: 競合解決、エンドツーエンド暗号化、ユーザーが明示して有効化する無料運用を評価する。
